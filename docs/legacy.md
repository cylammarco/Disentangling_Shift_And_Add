# Original V2.0 workflow for triples

The installable `saad` workflow handles two stellar components. The original V2.0 scripts are retained under `example/legacy/` because they also implement triple disentangling and use a Python configuration file rather than YAML. They are separate from the high-level `saad.run` API.

| File | Purpose |
| --- | --- |
| `example/legacy/disentangle_shift_and_add.py` | Original binary/triple driver. |
| `example/legacy/Input_disentangle.py` | Editable Python variables for observations, orbit, light fractions, grid, and plots. |
| `example/legacy/Disentangling/disentangle_functions.py` | Original solver and format readers used by the driver. |
| `example/make_spectra_SB3.py` | Generator for synthetic triple observations, using templates in `Models/`. |

To try the synthetic triple from a fresh checkout after installing package dependencies:

```bash
cd example
python make_spectra_SB3.py
# Edit legacy/Input_disentangle.py as described below.
MPLBACKEND=Agg python legacy/disentangle_shift_and_add.py
```

In `legacy/Input_disentangle.py`, set `CompNum = 3`, `GridDis = False`, and `NumItrFinal = 100` for a direct example run. The supplied inner and outer orbital parameters and `lguessVec = [0.3, 0.3, 0.]` match the SB3 generator. The driver reads `obs/` and writes `Output/` relative to the **current working directory**. Like the SB2 generator, `make_spectra_SB3.py` replaces matching files in `obs/`; use a fresh working directory when preserving observations matters.

The archived scripts have a different data path convention: `ObsDat.txt` rows generated by `make_spectra_SB3.py` already contain `obs/` prefixes. The installable CLI expects filenames relative to its configured `obs_path`. Use `example/make_spectra_SB2.py` and `example/quickstart.yaml` for the modern binary workflow.

The [archived upstream documentation](https://github.com/cylammarco/Disentangling_Shift_And_Add/blob/main/example/legacy/README.md) contains the original extended scientific discussion and parameter notes. It describes the upstream layout; use the paths on this page for this fork.
